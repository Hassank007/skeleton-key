# Hook run, 2026-11-23

Evidence that the Kiro hooks fire. Written by Claude Code from the Kiro CLI output and `.kiro/hook-runs.log` (both local files).

**Why this exists.** The first four hooks were written in Kiro's legacy `.kiro.hook` format and had not run when the apps were built. Nobody had checked. On 2026-11-23 Kiro converted them to the current format (`scripts/kiro-batches/18-hooks-current-format.txt`).

**How it was tested.** Kiro CLI 3.4.0, `kiro-cli chat --no-interactive --trust-all-tools --trust-workspace`, with the prompt in `scripts/kiro-batches/20-hook-probe.txt`. The prompt made Kiro write a deliberately bad component: a `div` with a click handler around an image with no alt text. It also told Kiro that this was a hook test, so this shows that the hooks fire. It does not show that Kiro would have written bad code by itself.

| Hook | Fired? | What happened |
|---|---|---|
| `a11y-guard` (PostFileSave) | Yes, after both writes | Told Kiro to review the file against the accessibility steering. Kiro removed the click handler and hid the decorative image from assistive technology. Kiro said it used the rules already in its context and did not re-read the steering file. |
| `a11y-guard-agent` (PostToolUse) | Yes, after both writes | ESLint found 3 jsx-a11y violations in the first write and none in the second. Its printed output did not reach the agent, so the log is the evidence. |
| `test-buddy` (PostFileCreate) | Yes, once | Asked for a test file. Kiro did not write one, because the probe prompt said to change no other file. |
| `skeleton-sync` (PostFileSave) | Yes, after both writes | Kiro checked both apps and found that neither used the component. |

The log lines:

```text
2026-11-23T19:05:21.826Z  a11y-guard-agent  skeleton/src/components/HookProbe.tsx  3 jsx-a11y violation(s): jsx-a11y/click-events-have-key-events, jsx-a11y/no-static-element-interactions, jsx-a11y/alt-text
2026-11-23T19:05:33.216Z  a11y-guard-agent  skeleton/src/components/HookProbe.tsx  no jsx-a11y violations
```

The probe file was deleted afterwards.

**A real change with the hooks on.** The same evening Kiro fixed an open finding from its own Trusted Tester review: `Button` had no default `type="button"` (`scripts/kiro-batches/21-button-type-with-hooks.txt`). `a11y-guard` fired and Kiro found nothing to fix. `skeleton-sync` fired and named the two apps that needed the same change. `a11y-guard-agent` logged no jsx-a11y violations. `test-buddy` did not fire, because no component file was created.

**Surprise.** Kiro's own notes say PostFileSave fires when a person saves a file. In the CLI it also fired after the agent's own writes.

**Not tested:** the hooks in the Kiro IDE.
